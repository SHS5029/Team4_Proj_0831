## 1. 시나리오 목적

시나리오는 복잡한 사건 해결 퍼즐이 아니라, 플레이어가 대화를 시작할 수 있도록 사건의 배경과 분위기를 제공하는 역할을 한다.

- 모든 플레이어는 사건 현장에 있었다.
- 피해자는 게임 시작 전에 사망한 상태다.
- 정적 시나리오 자체에는 특정 좌석으로 고정된 범인이 없다.
- 역할 배정 뒤 마피아 역할을 받은 플레이어가 해당 사건의 독립 연루자다.
- 마피아가 2명이면 둘 다 사건에 독립적으로 연루된 범인으로 취급하며, 사전 공모나
  공범 관계를 전제하지 않고 서로의 정체·행동·개인 정보를 알 수 없다.
- 게임의 목표는 범행 방법이나 동기를 맞히는 것이 아니라 마피아를 찾는 것이다.
- 시나리오 자체만으로 범인을 알 수 없어야 한다.
- 복잡한 사건보드와 다수의 핵심 단서는 사용하지 않는다.

## 2. 공통 사건 정보

모든 플레이어에게 다음 정보를 공개한다.

- 시나리오 제목
- 사건 배경
- 피해자
- 사건 장소
- 현장에 있던 플레이어
- 마피아를 찾아야 한다는 목표

백엔드는 저장된 게임 seed와 정적으로 검증된 카탈로그를 사용해 각 플레이어에게
개인적으로 다음 정보를 정확히 하나씩 제공한다.

- 한 문장의 알리바이
- 한 문장의 관찰 정보
- 자신의 역할과 역할 능력

알리바이와 관찰 정보는 외우기 쉽도록 짧게 작성한다. 정확한 분 단위 시간, 복잡한 이동 경로, 인물 간 관계도는 제공하지 않는다.
같은 `scenario_version`, 시나리오 ID, 게임 seed, 인원과 좌석 배치에는 항상 같은
알리바이·관찰 정보가 배정되어야 하며 저장 게임을 불러와도 다시 추첨하지 않는다.
LLM은 카탈로그에 없는 사건 사실, 알리바이 또는 관찰 정보를 새로 만들 수 없다.

## 3. 시나리오 1: 정전된 방송국

### 사건 설명

생방송을 준비하던 방송국에서 PD가 사망했습니다. 정전 당시 방송국에 있던 사람 중
마피아 역할의 플레이어를 찾아야 합니다.

### 피해자

생방송 PD

### 장소 4~5개

스튜디오, 조정실, 분장실, 대기실, 장비실

### 플레이어별 알리바이 1개

카탈로그에서 각 좌석에 사건 당시 위치와 행동을 설명하는 알리바이 한 개를 배정한다.
예시: “정전 당시 조정실에서 방송 장비를 확인하고 있었다.”

### 플레이어별 관찰 정보 1개

카탈로그에서 각 좌석에 다른 플레이어의 행동이나 소리를 설명하는 관찰 정보 한 개를
배정한다. 예시: “정전 직전 누군가 장비실 방향으로 이동하는 것을 봤다.”

## 8. 카탈로그 배치와 정적 검증 규칙

`scenario-v1`은 런타임 LLM 생성물이 아니라 사전에 작성·검증한 정적 카탈로그다.
각 카탈로그 항목은 시나리오 ID, 공개 사건 정보, 6~9명별 알리바이·관찰 정보 후보,
좌석 배치 규칙과 검증 결과를 가진다. 백엔드는 게임 생성 시 저장된 seed로 후보와
좌석만 결정적으로 배치한다.

### 콘텐츠 준비 상태와 승인 게이트

3~7절의 알리바이·관찰 문장은 콘텐츠 방향을 보여 주는 예시이며 배포 가능한 전체
카탈로그가 아니다. Backend `WU-B2`에서 시나리오별 최대 9좌석을 지원하도록 최소
9개 알리바이와 9개 관찰 template, 즉 5종 전체에 최소 90개 template record를
정적으로 작성해야 한다. 관찰 record에는 대상 placeholder 또는 명시적 익명 표식을
포함한다. 제품 담당자가 역할 중립성·문장 간 무모순·6~9명 배치 결과를 검수해
승인하기 전에는 `scenario-v1` 콘텐츠 완료나 Backend `CP-B1` 통과로 간주하지 않는다.
검수되지 않은 빈칸을 LLM 생성 문구로 채우지 않는다.

배포 전에 모든 시나리오를 다음 기준으로 검증한다.

- 6~9명 모든 인원 구성에서 각 좌석에 알리바이와 관찰 정보가 정확히 하나씩 배정된다.
- 같은 입력에는 같은 결과가 나오고, 다른 게임의 좌석·역할·비공개 정보가 섞이지 않는다.
- 마피아가 2명이어도 서로를 알거나 공모했다는 사실을 어떤 개인 정보에도 넣지 않는다.
- 알리바이·관찰 정보만으로 특정 역할이나 범인을 확정할 수 없다.
- 공개 배경, 장소, 알리바이와 관찰 정보 사이에 논리적 모순이 없다.
- 역할 배정 전후 어느 단계에서도 LLM이 카탈로그 문장을 추가·변경하지 않는다.

### 알리바이

- 모든 역할이 자연스럽게 주장할 수 있어야 한다.
- 마피아의 알리바이가 처음부터 거짓처럼 보이면 안 된다.
- 시민의 알리바이도 대화 과정에서 의심받을 수 있어야 한다.
- 알리바이만으로 범인을 확정할 수 없어야 한다.
- 정확한 분 단위 시간은 사용하지 않는다.

### 관찰 정보

- 다른 플레이어의 행동이나 소리를 하나만 관찰한다.
- 관찰 대상의 역할을 직접 알려주지 않는다.
- 사실이어도 여러 가지로 해석할 수 있어야 한다.
- 모든 플레이어에게 핵심 단서를 제공하지 않는다.
- 관찰 정보끼리 완전히 모순되지 않아야 한다.
- 특정 플레이어를 관찰한 항목은 관찰자 자신이 아닌 대상 좌석 ID를 함께 저장한다.
- “누군가”처럼 익명인 항목은 카탈로그에 익명 관찰로 명시하며, 런타임에 임의의
  플레이어 이름을 붙이지 않는다.

## 9. 시나리오 선택 규칙

백엔드는 사용자별로 시나리오 5개 중 하나를 저장된 seed에 따라 결정적으로 선택한다.

- 해당 사용자가 직전에 성공적으로 생성한 게임과 같은 시나리오는 선택하지 않는다.
- 첫 게임에는 제외 대상이 없다.
- 현재 게임의 시나리오 팩 버전, 시나리오 ID, seed와 배치 snapshot을 저장한다.
- 다음 게임 생성 시 사용자별 직전 시나리오 ID를 후보에서 제외한다.
- 남은 시나리오 중 하나를 저장된 seed로 결정적으로 선택한다.
- 시나리오를 모두 한 번씩 사용한 뒤에도 직전 시나리오 제외 규칙은 유지한다.
- 동시 생성 요청은 백엔드가 사용자 단위로 직렬화하여 같은 직전 ID를 기준으로
  중복 선택하거나 사용자 기록을 덮어쓰지 않게 한다.

```text
이전 시나리오 ID 저장
→ 다음 시나리오 후보에서 제외
→ 남은 시나리오 중 seed 기반 결정적 선택
```

MVP에서는 사용자별 직전 시나리오 ID 하나만 유지하며 복잡한 전체 이력이나 추천
알고리즘은 구현하지 않는다. 저장 게임 불러오기와 재접속에서는 저장된 snapshot을
재사용하고 시나리오나 개인 정보를 다시 선택하지 않는다.

## 10. 밸런스 원칙

- 모든 시나리오는 동일한 역할 규칙을 사용한다.
- 특정 시나리오에서 탐정이나 의사가 더 유리해지지 않도록 한다.
- 특정 장소나 물건이 마피아를 자동으로 지목하지 않도록 한다.
- 사건 배경만으로 정답을 알 수 없어야 한다.
- 시나리오마다 알리바이 1개와 관찰 정보 1개만 제공한다.
- 시나리오의 차이는 장소와 분위기에서 만들고, 승패는 대화와 투표로 결정한다.
- AI 페르소나는 말투·감정 표현·발언 성향만 달리한다. 역할별로 허용된 정보 차이
  외에는 페르소나별 추론 능력과 정보 접근 권한을 동일하게 적용한다.
