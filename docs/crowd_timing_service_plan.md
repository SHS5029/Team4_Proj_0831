# 틈새 서비스 기획안

## 1. 서비스 개요

**틈새**는 관광지와 도심 명소의 혼잡도를 분석해 사용자가 덜 붐비는 장소와 시간을 선택하도록 돕는 AI 나들이 에이전트다.

- 전국 관광지의 향후 30일 혼잡도 비교
- 서울 주요 장소의 실시간 한산도 탐색
- 벚꽃·단풍·축제의 최적 관람 시점 추천
- 사용자 위치를 반영한 출발시간과 대체 장소 안내

핵심 가치는 단순한 장소 추천이 아니라 **언제, 어디로, 몇 시에 출발할지** 결정해 주는 것이다.

## 2. 핵심 기능

| 모드 | 사용자 질문 | 제공 결과 |
| --- | --- | --- |
| 언제 갈까 | “에버랜드는 언제 덜 붐빌까?” | 30일 혼잡 캘린더, 한산한 날짜 Top 3 |
| 지금 어디 갈까 | “지금 한강 어디가 한산해?” | 주변 실시간 혼잡도, 즉석 나들이 코스 |
| 이번 시즌 | “이번 주말 벚꽃 어디가 좋을까?” | 관람 적기, 예상 혼잡도, 대체 명소 |

공통 결과에는 혼잡점수, 신뢰도, 판단 근거, 추천 출발시간과 플랜 B를 포함한다.

## 3. 사용자 흐름

1. 사용자가 장소·지역·테마 중 하나를 선택한다.
2. 날짜 변경 가능 범위, 이동수단, 동행 유형을 입력한다.
3. 앱이 관광·날씨·교통·행사 데이터를 수집한다.
4. 혼잡도 엔진이 장소별·날짜별 점수와 신뢰도를 계산한다.
5. AI Agent가 추천 이유, 이동 일정과 대체 장소를 설명한다.

### 핵심 데이터 원칙

- 관광공사 집중률을 기본값으로 사용하고 날씨·검색 급증·신규 행사로 보정한다.
- 공휴일과 계절 특성은 기본 집중률에 이미 일부 반영될 수 있으므로 단순 중복 가산하지 않는다.
- 공식 집중률 데이터가 없는 관광지는 지역 단위 대체값을 사용하고 신뢰도를 낮게 표시한다.
- 30일 날씨를 임의 예측하지 않고, 방문일이 가까워질수록 단기예보와 실시간 데이터로 갱신한다.

## 5. 혼잡도 계산 구조

```text
기본 점수 = 관광공사 30일 집중률
사전 보정 = 날씨 변화 + 검색량 변화 + 행사 + 운영정보
당일 보정 = 실시간 인구 + 진입도로 교통 + 사용자 제보
최종 결과 = 혼잡점수 + 신뢰도 + 판단 근거
```

정확한 수치 계산은 예측 모델이 담당하고, AI Agent는 계산 결과를 설명하고 사용자 행동으로 연결한다.

## 6. MCP·AI Agent 구성

- **MCP 데이터 연결 계층:** 관광, 날씨, 교통, 행사, 검색, 캘린더 데이터 호출
- **혼잡도 엔진:** 정규화, 데이터 결합, 혼잡점수와 신뢰도 계산
- **AI Agent:** 사용자 조건 해석, 추천 이유 설명, 일정·대체 장소 생성
- **알림 기능:** 혼잡도 급변, 출발 권장 시각, 시즌 관람 적기 안내

## 7. MVP 범위

- 관광공사 집중률 API가 지원하는 관광지 50~100곳
- 서울 실시간 도시데이터 지원 장소
- 벚꽃·단풍 대표 장소 10~20곳
- 30일 혼잡 캘린더와 한산한 날짜 Top 3
- 현재 위치 기반 실시간 한산 레이더
- 추천 출발시간과 대체 장소 1곳
- 혼잡도 변화 알림과 사용자 혼잡도 제보

첫 구현 단계에서는 관광지 집중률 API의 전체 지원 장소를 수집해 실제 서비스 대상 목록을 확정한다.

## 8. 초기 제약

- 민간 관광지의 일별·시간대별 실제 입장객 수는 일반적으로 공개되지 않는다.
- 어트랙션별 실시간 대기시간, 예매 잔량, 주차장 점유율은 공식 공개 API가 없을 수 있다.
- 초기에는 “정확한 대기시간”보다 “덜 붐빌 날짜와 출발시간”을 제공한다.
- 로그인 후 노출되는 앱 데이터를 무단 수집하지 않고, 공식 API·관리자 입력·제휴 데이터만 사용한다.

### 9.2 공공데이터포털 활용신청 체크리스트

공공데이터포털 키 하나만 발급받아도 데이터셋을 자동으로 쓸 수 있는 것은 아니다. 다음 상세 페이지에서 각 API의 **활용신청**을 완료하고, 마이페이지에서 승인 상태·호출 주소·트래픽 한도를 확인한다.

- [한국관광공사 관광지 집중률 방문자 추이 예측 정보](https://www.data.go.kr/data/15128555/openapi.do): 향후 30일 기본 혼잡도
- [한국관광공사 국문 관광정보 서비스_GW](https://www.data.go.kr/data/15101578/openapi.do): 관광지, 좌표, 행사, 이미지와 운영정보
- [한국천문연구원 특일 정보](https://www.data.go.kr/data/15012690/openapi.do): 공휴일과 대체휴일
- [기상청 단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do): 초단기실황·초단기예보·단기예보
- [기상청 중기예보 조회서비스](https://www.data.go.kr/data/15059468/openapi.do): 단기예보 이후의 중기 날씨 보정
- [기상청 기상특보 조회서비스](https://www.data.go.kr/data/15000415/openapi.do): 호우·폭염·강풍 등 방문 위험 보정
- [한국관광공사 빅데이터 지역별 방문자수_GW](https://www.data.go.kr/data/15101972/openapi.do): 지역 단위 과거 방문자 보조값. MVP에서 관광지 집중률만으로 시작하면 후순위로 미뤄도 된다.

공공데이터포털에서 표시하는 인코딩 키와 디코딩 키를 혼용해 이중 URL 인코딩하지 않는다. 애플리케이션에는 원본 키 하나만 저장하고 HTTP 클라이언트가 쿼리 파라미터를 한 번만 인코딩하도록 한다.

### 9.4 키가 필요 없는 데이터와 내부 비밀값

- [전국관광지정보표준데이터](https://www.data.go.kr/data/15021141/standard.do)는 CSV 파일 다운로드 방식이므로 API 키가 필요 없다.
- [주요관광지점 입장객통계](https://know.tour.go.kr/stat/visitStatDis/table.do)는 공개 통계 조회·다운로드 자료다. 공개 API 계약이 확인되기 전에는 월간 배치 입력 자료로 취급한다.
- 관광지 공식 홈페이지의 운영시간·휴무·시설 운휴와 관리자 입력에는 API 키가 없다. 이용약관을 확인하고 수동 또는 허용된 방식으로 갱신한다.
- `DATABASE_URL`, `auth.cookie_secret`, 푸시 알림 서비스 계정은 API 발급 목록과 별개의 내부 비밀값이다. 알림 클라이언트 기술이 정해지기 전에는 Firebase 등 특정 공급자의 키를 미리 발급하지 않는다.

### 9.5 발급 순서

1. 공공데이터포털 계정을 만들고 9.2의 핵심 API 활용신청을 완료한다.
2. 서울 열린데이터광장 인증키와 카카오 REST API 키를 발급해 실시간 혼잡도·이동시간 경로를 확보한다.
3. 현재 로그인 구현에 필요한 Google OAuth Client를 설정한다.
4. 사용할 LLM 공급자를 확정하고 서버용 프로젝트 API 키를 발급한다.
5. 핵심 데이터 파이프라인이 동작한 뒤 NEIS, NAVER API HUB, YouTube를 순서대로 추가한다.

모든 키는 개발·운영 환경을 분리하고 최소 권한, 호출량 제한, 도메인·IP 제한을 적용한다. 실제 키를 `.env.example`, `secrets.toml.example`, 로그, 오류 메시지 또는 Git 이력에 남기지 않는다.
