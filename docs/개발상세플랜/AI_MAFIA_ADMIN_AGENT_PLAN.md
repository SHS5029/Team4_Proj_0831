# AI 마피아 관리자 운영 에이전트 계획서

## 1. 문서 목적

이 문서는 관리자 센터에서 RAG 기반 운영 에이전트를 도입하기 위한 설계 계획이다.
현재 관리자 화면에는 `운영 에이전트 계획` 탭과 승인 자료를 검색하는 질문 UI를 둔다.
검색은 외부 LLM 없이 고정 차원 로컬 임베딩과 PostgreSQL pgvector를 사용한 추출형
요약으로 먼저 구현하며, 자동 데이터 변경 기능은 구현하지 않는다.

현재 연결된 원격 PostgreSQL에서는 `vector` extension이 제공되지 않는 것이 확인되었다.
따라서 코드·migration·색인 명령은 준비했지만, 실제 질문을 활성화하려면 DB 담당자가
pgvector 설치 가능 여부를 먼저 확인하고 `005` migration과 색인 명령을 순서대로 적용해야 한다.

목표는 정보를 무작정 나열하는 에이전트가 아니라, 관리자의 질문에 맞는 승인 자료를
찾아 짧게 요약하고 출처와 신뢰도를 함께 보여 주는 read-only 관리자 도우미다.

## 2. 이미지 요구사항 반영

참조 이미지의 네 가지 요구를 다음과 같이 설계에 반영한다.

1. 피드백·공개 게임 요약·운영 문서만 정제하고 벡터화한다. 개인정보, 비밀키, prompt,
   비공개 역할 정보는 색인 대상에서 제외한다.
2. PostgreSQL과 `pgvector`를 사용해 키워드 검색과 유사도 검색을 함께 수행한다.
3. 관리자의 질문에 대해 답변, 근거 문서, 신뢰도를 반환한다.
4. 모든 조회를 감사 로그에 남기며 에이전트가 자동으로 수정·삭제·강제 종료를 수행하지
   못하게 제한한다.

## 3. 관리자 사용 시나리오

관리자는 다음 순서로 사용한다.

1. 운영 분석에서 KPI·진영 승률·페르소나 승률을 확인한다.
2. 사용자 피드백에서 기간·종류·평점으로 개선 의견을 좁힌다.
3. 운영 에이전트에 “최근 낮은 평점에서 반복되는 문제는 무엇인가?”처럼 질문한다.
4. 에이전트는 요약, 출처 목록, 신뢰도, 근거 부족 여부를 보여 준다.
5. 관리자는 원본 피드백 또는 운영 문서로 이동해 최종 판단한다.

에이전트는 판단을 대신하지 않는다. 답변 근거가 부족하면 추측하지 않고 `추가 확인
필요`를 반환한다.

## 4. 데이터 경계

| 구분 | 허용 범위 | 처리 방법 |
|---|---|---|
| 사용자 피드백 | 공개 목록 필드, 평점, 유형, 태그, 작성 시각 | 개인정보 제거 후 문장 단위 chunk |
| 종료 게임 | 결과 화면에 공개되는 사건·승패·진행 요약 | game ID·시나리오·기간 메타데이터 부여 |
| 운영 문서 | 승인된 API 명세, 화면 흐름, 운영 가이드 | 문서 버전·절·갱신 시각 보존 |
| 관리자 감사 | 조회 유형·요청 ID·시각 같은 메타데이터 | 원문 payload와 비밀값은 저장하지 않음 |
| 제외 정보 | API 키, DB URL, token, private prompt, 진행 중 역할·행동 | 수집·embedding·답변 모두 차단 |

원문을 그대로 모델에 전달하지 않고, 검색 결과에도 관리자에게 공개해도 되는 필드만
포함한다. 임베딩 데이터에도 동일한 allowlist를 적용한다.

## 5. 권장 처리 흐름

```text
승인 자료 수집
  -> 개인정보·비밀값 제거 및 문서 버전 부여
  -> chunk와 embedding 저장
  -> 키워드 검색 + pgvector 유사도 검색
  -> 권한·기간·유형 필터와 재순위화
  -> 근거가 있는 부분만 요약
  -> 출처·신뢰도·근거 부족 여부 반환
  -> 관리자 조회 감사 로그 기록
```

### 5.1 색인 단계

- `source_type`, `source_id`, `document_version`, `scenario_id`, `created_at`, `visibility`
  메타데이터를 필수로 저장한다.
- 동일 문서가 다시 들어오면 content hash로 변경 여부를 확인하고, 이전 버전은 보존한다.
- 삭제·비공개 전환된 원문은 검색 결과에서 즉시 제외하며 embedding도 정리 대상에 표시한다.
- 최초 데이터는 실제 개인정보가 아닌 합성 피드백과 승인 문서로 품질을 검증한다.

### 5.2 검색 단계

- 질문을 정규화한 뒤 PostgreSQL full-text 검색과 `pgvector` cosine similarity를 함께 실행한다.
- `scenario_id`, 기간, feedback type, rating, source type 같은 구조화 필터를 먼저 적용한다.
- 상위 `top_k` 결과를 source hash와 함께 재순위화하고, 답변에 사용한 근거만 전달한다.
- 검색 결과가 임계값보다 낮으면 답변을 생성하지 않고 근거 부족 상태를 반환한다.

## 6. 구현한 API

아래 API는 WU-B10에서 Backend 계약에 추가한 read-only 검색 API다. 질문을 위한 POST지만
게임·문서·사용자 데이터를 변경하지 않으며, 운영 색인은 별도 수동 명령으로 실행한다.

### `POST /api/v1/admin/insights/query`

요청 예시:

```json
{
  "question": "최근 낮은 평점에서 반복되는 문제는 무엇인가?",
  "filters": {
    "source_types": ["FEEDBACK", "OPERATIONS_DOC"],
    "rating_lte": 2,
    "from": "2026-09-01T00:00:00Z",
    "to": "2026-09-07T23:59:59Z"
  },
  "top_k": 5
}
```

응답 예시:

```json
{
  "answer": "사건 설명의 이해도와 토론 진행 안내가 반복적으로 언급되었습니다.",
  "confidence": "MEDIUM",
  "has_sufficient_evidence": true,
  "sources": [
    {"source_type": "FEEDBACK", "source_id": "feedback:2026-09-07-001", "score": 0.82},
    {"source_type": "OPERATIONS_DOC", "source_id": "screen-flow:v1.2#15.2", "score": 0.71}
  ],
  "request_id": "<uuid>",
  "generated_at": "<timestamp>"
}
```

현재 구현의 답변은 검색 상위 청크를 연결하는 추출형 요약이며, 외부 LLM이나 내부
추론 전문은 사용하지 않는다. 필수 보호 조건은 다음과 같다.

- 기존 관리자 UUID allowlist를 통과한 요청만 허용한다.
- 응답은 `answer`, `confidence`, `sources`, `has_sufficient_evidence`로 제한한다.
- DB write, 게임 command, 문서 삭제, 사용자 알림 전송 도구는 이 API에 연결하지 않는다.
- 질문 원문은 저장하지 않고 action·request ID·결과 상태만 감사 로그에 남긴다. 질문에
  비밀값 조회 의도가 섞이면 API 경계에서 거부한다.

## 7. 도입 순서

| 단계 | 구현 범위 | 완료 기준 |
|---|---|---|
| 1. 자료 기반 | allowlist, chunk 규칙, version/hash, 합성 데이터 | `005` schema와 수동 색인 명령 추가 |
| 2. 검색 품질 | full-text + pgvector, metadata filter, top-k | 혼합 검색과 유사 자료 출처 반환 |
| 3. 답변 API | read-only 관리자 endpoint, 근거·신뢰도 응답 | `POST /insights/query`와 감사 action 연결 |
| 4. 운영 검증 | 질문 평가셋, latency·hit rate·feedback loop | 관리자 승인 후에만 다음 단계 진행 |

처음부터 자동 조치까지 연결하지 않는다. 30~50개의 합성 질문으로 검색 결과와 출처가
맞는지 평가한 뒤, 실제 운영 자료를 단계적으로 추가한다.

## 8. 관리자 UX 계획

현재 추가한 `운영 에이전트 계획` 탭은 다음 내용을 한 화면에 보여 준다.

- 외부 LLM과 자동 조치는 아직 연결되지 않았음을 알리는 구현 상태 배지
- 자료 수집·벡터화·근거 답변·감사 보호의 네 단계 흐름
- 관리자 질문과 답변 예시
- 허용·제외 데이터 경계
- 단계별 도입 계획과 자동 조치 차단 원칙
- 승인 자료 질문 입력창, 근거 문장, 점수, 신뢰도와 근거 부족 상태

실제 색인은 `backend/index_admin_knowledge.py`를 수동 실행한다. 질문 시점에는 색인
테이블을 읽기만 하므로, 관리자의 질문이 게임 상태나 운영 자료를 바꾸지 않는다.

## 9. 이번 작업의 제외 범위

- 외부 LLM·embedding provider 호출. 현재는 로컬 feature-hashing 임베딩을 사용한다.
- 자동 알림·게임 변경·데이터 삭제 agent tool

DB에 pgvector를 설치할 권한이 없는 환경에서는 이 기능을 억지로 다른 포트나 별도 DB로
우회하지 않는다. 관리자 화면은 기존 운영 분석·피드백·로그를 계속 표시하고, 색인 테이블이
없는 동안 질문 결과는 의존성 오류로 안전하게 중단한다.

이 범위는 별도 작업 단위로 승인·검증해야 하며, 현재 관리자 read-only API와 합쳐서
배포하지 않는다.
